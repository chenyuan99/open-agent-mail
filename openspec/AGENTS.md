# OpenSpec instructions

1. Read `../AGENT.md`, `project.md`, and the complete active change before editing implementation code.
2. Keep `proposal.md` focused on why, scope, capabilities, and impact.
3. Put verifiable behavior in `specs/<capability>/spec.md` using `### Requirement:` and at least one `#### Scenario:` with GIVEN/WHEN/THEN bullets.
4. Put architecture, protocols, data models, security decisions, and tradeoffs in `design.md`.
5. Put ordered implementation and validation work in `tasks.md` with checkboxes.
6. Do not check off a task before its implementation and verification are complete.
7. Do not archive a change until every required task and scenario has evidence.
8. When archiving, sync the complete future-state spec to `openspec/specs/<capability>/spec.md` and move the change to `openspec/changes/archive/YYYY-MM-DD-<change-name>/`.
